# Minimal relay deployment

One MoQ droplet and one Iroh droplet in DigitalOcean London (`lon1`), each using Ubuntu 24.04 and `s-1vcpu-2gb` (1 vCPU, 2 GB RAM). Cloudflare provides DNS; Let's Encrypt provides public TLS certificates. Docker Compose runs the relays.

Gatekeeper is deployed separately. This stack takes its existing HTTPS origin and exports the relay bindings to configure there. It creates no Worker, Worker route, database, or Hyperdrive resources.

## Configure and deploy

From the repository root:

```sh
pnpm install
pnpm --filter @conservationtv/controlplane-infrastructure build
cd apps/controlplane/infrastructure
```

Use the repository's [Pulumi credentials workflow](../../../docs/infra/pulumi.md) for the commands below. From this directory, the wrapper is `op run --env-file=../../../.env.pulumi -- pulumi …`.

```sh
pulumi stack select dev
pulumi config set domain example.com
pulumi config set zoneId CLOUDFLARE_ZONE_ID
pulumi config set acmeEmail ops@example.com
pulumi config set sshCidr YOUR_PUBLIC_IP/32
pulumi config set gatekeeperUrl https://gatekeeper.example.com
pulumi config set --secret digitalocean:token
pulumi config set --secret cloudflare:apiToken
pulumi preview
pulumi up
```

The last two configuration commands prompt for the provider tokens. The Cloudflare token needs DNS access for the configured zone. Supply the gatekeeper's origin only, without an API path.

Allow SSH from the machine running Pulumi: deployment connects to the droplets on port 2222. For stack `dev`, relay addresses are `https://moq-dev.example.com/` and `https://iroh-dev.example.com/`. Both records are DNS-only so clients connect directly to the relays.

## Configure the existing gatekeeper

Read these stack outputs and apply them through gatekeeper's own deployment:

| Output                       | Gatekeeper inputs                                             |
| ---------------------------- | ------------------------------------------------------------- |
| `gatekeeperSecrets` (secret) | `MOQ_RELAY_TOKEN`, `MOQ_CLUSTER_TOKEN` and `IROH_RELAY_TOKEN` |

```sh
pulumi stack output gatekeeperSecrets --json --show-secrets
```

This command reveals credentials; use a private terminal or consume the secret output directly in your deployment tooling. All three credentials are generated by `pulumi/random` and stored as Pulumi secrets. Gatekeeper also needs its existing consumer registrations, signing keys, database bindings, and migrations; this stack does not change them. Relay admission works after the exported bindings are applied to gatekeeper.

MoQ calls `/relays/moq/admission` with its generated relay key as HTTP Basic credentials. Iroh calls `/relays/iroh/admission` with its generated bearer token. There is only one MoQ node, so its static peer list is empty. Gatekeeper receives no node list.

`moqDirectory` and `irohDirectory` contain the public relay endpoints. `sshConfig` and secret `sshPrivateKey` provide administrative access.

## Renewal

Run `pulumi up --refresh` regularly to renew and redistribute public certificates when they have fewer than 30 days left. There is no background renewal service. To rotate the MoQ peer credential, increment `clusterTokenGeneration`, run `pulumi up`, and apply the changed `gatekeeperSecrets` output to gatekeeper.
