# Minimal relay deployment

One MoQ droplet and one Iroh droplet in DigitalOcean London (`lon1`), each using Ubuntu 24.04 and `s-1vcpu-2gb` (1 vCPU, 2 GB RAM). Cloudflare provides DNS; Let's Encrypt provides public TLS certificates. Docker Compose runs the relays.

There are two stacks of this program, each an environment of its own: `prod` (`conservation.tv`), which production services use, and `staging` (`staging.conservation.tv`), which trusted developers use from their local studio API. Each has its own relays, gatekeeper and consumer token. The third environment, local, is docker compose; see [gatekeeper's README](../gatekeeper/README.md#develop).

Each stack also owns gatekeeper's Worker, its PlanetScale Postgres database and Hyperdrive config, and all of its secrets. Gatekeeper's code is uploaded from its build as Worker versions; this stack routes traffic to the deployed version and owns the custom domain and cron trigger. See [Release gatekeeper](#release-gatekeeper).

## Configure and deploy

From the repository root:

```sh
pnpm install
pnpm --filter @conservationtv/controlplane-infrastructure build
cd apps/controlplane/infrastructure
```

Use the repository's [Pulumi credentials workflow](../../../docs/infra/pulumi.md) for the commands below. From this directory, the wrapper is `op run --env-file=../../../.env.pulumi -- pulumi …`.

```sh
pulumi stack select prod                             # or: pulumi stack init staging, the first time
pulumi config set domain example.com
pulumi config set zoneId CLOUDFLARE_ZONE_ID
pulumi config set acmeEmail ops@example.com
pulumi config set gatekeeperDomain gatekeeper.example.com
pulumi config set planetscaleOrganization conservationtv
pulumi preview
pulumi up
```

Neither provider token is stack config. The DigitalOcean provider reads `DIGITALOCEAN_TOKEN`, which `.env.pulumi` loads from the `digitalocean_api_token` item in the `conservationtv` 1Password vault. The Cloudflare provider, the ACME DNS challenge and `cf` all read `CLOUDFLARE_API_TOKEN`, which `.env.pulumi` loads from the `cloudflare_api_token` item in the `conservationtv` 1Password vault. It is a user token, "pulumi controlplane prod (conservation.tv)", with `Zone Read`, `DNS Write` and `Workers Routes Write` on the zone and `Workers Scripts Write` and `Hyperdrive Write` on its account. The Cloudflare account is the zone's. The PlanetScale provider reads a service token from `PLANETSCALE_SERVICE_TOKEN_ID` and `PLANETSCALE_SERVICE_TOKEN`; `.env.pulumi` reads both from the `planetscale_service_token` item in the `conservationtv` 1Password vault. The token (`pulumi-controlplane`) has only the organization accesses `create_databases`, `read_databases` and `read_organization`: PlanetScale grants a token full access to the databases it creates, so it controls the gatekeeper databases (`gatekeeper`, `gatekeeper-staging`) and nothing else. `gatekeeperDomain` is the hostname gatekeeper is served on; relays call back to `https://<gatekeeperDomain>`.

Gatekeeper's database is `gatekeeper` in `aws-eu-west-2` on `PS_5_AWS_X86` (PS-5 is only offered on x86 in London; `databaseClusterSize` overrides it). Account-wide names (the Worker, its database and Hyperdrive config) are `gatekeeper` for prod and `gatekeeper-<stack>` otherwise; the stack exports the Worker's name as `gatekeeper.workerName`, which the upload reads. The PlanetScale provider creates it with its `main` branch and cannot choose single-node, so it runs as HA (a primary and two replicas). The branch is protected in Pulumi and deletion-protected in PlanetScale. The Worker connects through Hyperdrive as the read/write `gatekeeper` role; migrations run as `gatekeeper_migrate`, which inherits `postgres`. The PlanetScale SDK in `sdks/` is generated by `pulumi package add terraform-provider planetscale/planetscale 1.12.0`; rerun it to upgrade.

Deployment connects to the droplets over SSH on port 2222. SSH is key-only and open to any source, so `pulumi up` works from CI as well as a workstation. Relays are named `<service>.<site>.nodes.<domain>`: `https://moq.ldn1.nodes.example.com/` and `https://iroh.ldn1.nodes.example.com/`. Both records are DNS-only so clients connect directly to the relays. Each droplet raises the UDP socket buffer ceiling to 8 MiB for QUIC.

## Release gatekeeper

Gatekeeper releases like an image: upload a version as the artefact, then deploy it by tag. The [`controlplane` workflow](../../../.github/workflows/controlplane.yml) releases `staging` on every push to `main` that touches the controlplane, the fleet package or the lockfile. `prod` is released by running it by hand (`gh workflow run controlplane -f stack=prod`) on a commit staging already runs. It runs in the GitHub environment named after the stack, which only `main` can deploy to, and:

1. runs `pulumi up` without `gatekeeperVersion`, applying infrastructure changes while keeping the deployed version;
2. applies gatekeeper's migrations as `gatekeeperMigrationUrl`;
3. uploads a version tagged with the commit (`pnpm --filter @conservationtv/gatekeeper upload`), passing this stack's outputs as `STACK_OUTPUT_JSON` for the Hyperdrive binding and `gatekeeperSecrets` as the version's secrets;
4. runs `pulumi up --config gatekeeperVersion=<commit>` to route traffic to it.

`gatekeeperVersion` is not kept in `Pulumi.prod.yaml`. When it is unset, the stack reads the deployed tag from its own last outputs and keeps it, so a `pulumi up` from a workstation never rolls gatekeeper back. To roll back, `pulumi up --config gatekeeperVersion=<earlier commit>`.

The `staging` and `prod` environments each hold `PULUMI_CONFIG_PASSPHRASE`, `PULUMI_STATE_ACCESS_KEY_ID`, `PULUMI_STATE_SECRET_ACCESS_KEY` (the state bucket's credentials, passed to Pulumi as `AWS_ACCESS_KEY_ID` and `AWS_SECRET_ACCESS_KEY`), `PLANETSCALE_SERVICE_TOKEN_ID`, `PLANETSCALE_SERVICE_TOKEN`, `CLOUDFLARE_API_TOKEN` and `DIGITALOCEAN_TOKEN` as secrets, copied from the 1Password items `.env.pulumi` refers to, and `CLOUDFLARE_ACCOUNT_ID` as a variable. The state backend is the project's `backend.url` in `Pulumi.yaml`; see [Pulumi](../../../docs/infra/pulumi.md). To rotate one, update 1Password and run `op read --no-newline <reference> | gh secret set <NAME> --env <stack> -R conservationtv/conservationtv`.

Secrets reach gatekeeper only with a release. After rotating one here, release to apply it. Uploads keep secrets that are not in the file.

The consumer token is generated per stack (`consumerTokenGeneration`, starting at 1) and released as `CONSUMER_TOKEN`; read it with `pulumi stack output gatekeeperConsumerToken --show-secrets`. Prod's goes to production services' `GATEKEEPER_TOKEN`; staging's lives in 1Password for trusted developers. To rotate, increment `consumerTokenGeneration`, release, and give its holders the new value: there is no overlap.

MoQ calls `/relays/moq/admission` with its generated relay key as HTTP Basic credentials. Iroh calls `/relays/iroh/admission` with its generated bearer token. There is only one MoQ node, so its static peer list is empty. Gatekeeper receives no node list.

`moqDirectory` and `irohDirectory` contain the public relay endpoints. `sshConfig` and secret `sshPrivateKey` provide administrative access.

## Renewal

Run `pulumi up --refresh` regularly to renew and redistribute public certificates when they have fewer than 30 days left. There is no background renewal service. To rotate the MoQ peer credential, increment `clusterTokenGeneration`, run `pulumi up`, and release gatekeeper.

Gatekeeper's MoQ signing keys are generated per generation (`controlplane-moq-<n>`, starting at 1): it signs with the current generation's key and still verifies the previous one's. To rotate, increment `moqSigningKeyGeneration` (`pulumi config set moqSigningKeyGeneration 2`) and push to `main`; tokens signed with the old key keep verifying until they expire. The previous key is dropped at the next rotation, so leave at least `MAX_CREDENTIAL_LIFETIME_SECONDS` (an hour) between rotations.
