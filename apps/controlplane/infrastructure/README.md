# Minimal relay deployment

One MoQ droplet and one Iroh droplet in DigitalOcean London (`lon1`), each using Ubuntu 24.04 and `s-1vcpu-2gb` (1 vCPU, 2 GB RAM). Cloudflare provides DNS; Let's Encrypt provides public TLS certificates. Docker Compose runs the relays.

This stack also owns gatekeeper's Worker, its PlanetScale Postgres database and Hyperdrive config, and all of its secrets. Gatekeeper's code is uploaded from its build as Worker versions; this stack routes traffic to the version tagged `gatekeeperVersion` and, once that is set, owns the custom domain and cron trigger. See [Release gatekeeper](#release-gatekeeper).

## Configure and deploy

From the repository root:

```sh
pnpm install
pnpm --filter @conservationtv/controlplane-infrastructure build
cd apps/controlplane/infrastructure
```

Use the repository's [Pulumi credentials workflow](../../../docs/infra/pulumi.md) for the commands below. From this directory, the wrapper is `op run --env-file=../../../.env.pulumi -- pulumi …`.

```sh
pulumi stack select prod
pulumi config set domain example.com
pulumi config set zoneId CLOUDFLARE_ZONE_ID
pulumi config set acmeEmail ops@example.com
pulumi config set gatekeeperDomain gatekeeper.example.com
pulumi config set --path 'moqSigningKids[0]' controlplane-moq-2026-10-12
pulumi config set moqSigningActiveKid controlplane-moq-2026-10-12
pulumi config set planetscaleOrganization conservationtv
pulumi config set --secret digitalocean:token
pulumi config set --secret cloudflare:apiToken
pulumi preview
pulumi up
```

The last two configuration commands prompt for the provider tokens. The Cloudflare token needs DNS, Workers Scripts, Workers Custom Domains and Hyperdrive access for the configured zone and its account. The Cloudflare account is the zone's. The PlanetScale provider reads a service token from `PLANETSCALE_SERVICE_TOKEN_ID` and `PLANETSCALE_SERVICE_TOKEN`; `.env.pulumi` reads both from the `planetscale_service_token` item in the `conservationtv` 1Password vault. The token (`pulumi-controlplane`) has only the organization accesses `create_databases`, `read_databases` and `read_organization`: PlanetScale grants a token full access to the databases it creates, so it controls `gatekeeper` and nothing else. `gatekeeperDomain` is the hostname gatekeeper is served on; relays call back to `https://<gatekeeperDomain>`.

Gatekeeper's database is `gatekeeper` in `aws-eu-west-2` on `PS_5_AWS_X86` (PS-5 is only offered on x86 in London). The PlanetScale provider creates it with its `main` branch and cannot choose single-node, so it runs as HA (a primary and two replicas). The branch is protected in Pulumi and deletion-protected in PlanetScale. The Worker connects through Hyperdrive as the read/write `gatekeeper` role; migrations run as `gatekeeper_migrate`, which inherits `postgres`. The PlanetScale SDK in `sdks/` is generated by `pulumi package add terraform-provider planetscale/planetscale 1.12.0`; rerun it to upgrade.

Deployment connects to the droplets over SSH on port 2222. SSH is key-only and open to any source, so `pulumi up` works from CI as well as a workstation. Relays are named `<service>.<site>.nodes.<domain>`: `https://moq.ldn1.nodes.example.com/` and `https://iroh.ldn1.nodes.example.com/`. Both records are DNS-only so clients connect directly to the relays. Each droplet raises the UDP socket buffer ceiling to 8 MiB for QUIC.

## Release gatekeeper

Gatekeeper releases like an image: upload a version as the artefact, then deploy it by tag. From the repository root, after this stack is up:

```sh
op run --env-file=.env.pulumi -- apps/controlplane/release.sh prod
```

[`release.sh`](../release.sh) applies gatekeeper's migrations as `gatekeeperMigrationUrl`, then uploads a version tagged with the current commit (`pnpm --filter @conservationtv/gatekeeper upload`). It passes this stack's outputs as `STACK_OUTPUT_JSON`, which supplies the Hyperdrive binding, and `gatekeeperSecrets` as the version's secrets. It then runs `pulumi up` on this stack with `gatekeeperVersion` set to that tag, which is saved to the stack's config file. To roll back, `pulumi up --config gatekeeperVersion=<earlier commit>`. The first `pulumi up` runs without `gatekeeperVersion`, since nothing has been uploaded yet; the first release then deploys gatekeeper and attaches its domain.

Secrets reach gatekeeper only with a release. After rotating one here, release to apply it. Uploads keep secrets that are not in the file.

MoQ calls `/relays/moq/admission` with its generated relay key as HTTP Basic credentials. Iroh calls `/relays/iroh/admission` with its generated bearer token. There is only one MoQ node, so its static peer list is empty. Gatekeeper receives no node list.

`moqDirectory` and `irohDirectory` contain the public relay endpoints. `sshConfig` and secret `sshPrivateKey` provide administrative access.

## Renewal

Run `pulumi up --refresh` regularly to renew and redistribute public certificates when they have fewer than 30 days left. There is no background renewal service. To rotate the MoQ peer credential, increment `clusterTokenGeneration`, run `pulumi up`, and release gatekeeper.

To rotate the MoQ signing key, add a kid to `moqSigningKids`, `pulumi up` and release. Then switch `moqSigningActiveKid` to it, `pulumi up` and release. Remove the old kid once its longest-lived token has expired.
