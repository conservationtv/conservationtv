# Edge agent (experiment)

Could the camera deliver its own exposures, instead of the agent's MediaMTX? This is a Rust version of the agent
runtime, small enough for an Axis camera to run as an ACAP app: it reports the device's metrics to the studio API,
signed as the device, publishes the camera's video to a MoQ relay, and serves its status over iroh. It is a spike,
not a product: nothing here is wired into the workspace, CI or the studio.

| Crate                        | What it is                                                                                     |
| ---------------------------- | ---------------------------------------------------------------------------------------------- |
| `sdkgen/downlevel.mjs`       | Rewrites the studio API's OpenAPI 3.1 contract as 3.0, which is all progenitor reads            |
| `studio-sdk`                 | The studio API's client, generated by progenitor at build time, with `Operation-Version` and RFC 9421 device signatures in its hooks |
| `edge-agent`                 | The runtime: machine metrics, a MoQ publisher (stdin Annex-B, or VDO with `--features axis`), status over iroh-http |
| `interop/verify-server.mjs`  | A stand-in for the studio API's device operations, verifying exactly as its middleware does    |
| `docker/Dockerfile.acap`     | A native (arm64 or amd64) builder with the ACAP Native SDK's sysroots                           |

## Running the experiments

```sh
# The SDK: regenerate the down-levelled contract after the API's changes.
node sdkgen/downlevel.mjs ../../apps/studio/api/contracts/openapi.json > studio-sdk/spec/openapi.3.0.json

# Signatures and bodies against the API's own verifier and Zod schema (needs `pnpm install` for studio-sdk).
KEY=$(openssl rand -hex 32)
node interop/verify-server.mjs $KEY 8787 &
AGENT_SECRET_KEY=$KEY STUDIO_API_URL=http://127.0.0.1:8787 cargo run -p edge-agent -- report

# MoQ: the deployed relay version, anonymous on anon/**, fed a test pattern standing in for the camera's encoder.
docker run -d --name ctv-moq-relay -p 4443:4443/udp -p 4443:4443/tcp -e MOQ_LISTEN='[::]:4443' \
  -e MOQ_LISTEN_TLS_GENERATE=localhost -e MOQ_WEB_HTTP_LISTEN='[::]:4443' -e MOQ_AUTH_PUBLIC='anon/**' \
  moqdev/moq-relay:0.17.2
ffmpeg -re -f lavfi -i testsrc=size=1280x720:rate=30 -c:v libx264 -preset ultrafast -tune zerolatency -g 60 \
    -bsf:v h264_mp4toannexb -f h264 - |
  AGENT_SECRET_KEY=$KEY IROH=1 MOQ_URL=http://localhost:4443/anon MOQ_BROADCAST=camera1 cargo run -p edge-agent -- run
curl localhost:4443/announced/anon                 # camera1
curl localhost:4443/fetch/anon/camera1/catalog.json

# Cameras: aarch64 (ARTPEC-8/9, CV25) and armv7hf (ARTPEC-6/7), linked against the SDK's glibc.
docker build -f docker/Dockerfile.acap -t edge-agent-acap docker
docker run --rm -v "$PWD":/src -v edge-agent-cargo:/usr/local/cargo/registry -v edge-agent-git:/usr/local/cargo/git \
  -v edge-agent-target:/target edge-agent-acap \
  cargo build --release -p edge-agent --target aarch64-unknown-linux-gnu --features axis
```

## Environment

`AGENT_SECRET_KEY` (32-byte hex seed, the device's identity), `STUDIO_API_URL`, `METRICS_INTERVAL_SECS`, `IROH=1`,
`MOQ_URL` (with `?jwt=` for a token), `MOQ_BROADCAST`, `EXPOSURE_ID`, `VIDEO_SOURCE` (`stdin` or `vdo`),
`VDO_CHANNEL`. On a camera these would be the app's parameters (`manifest.json`), read through `axparameter`, not
the environment: not done yet.

## What the builds produced (SDK 12.11.0, `--release --features axis`)

| Target                                 | Size    | Needs                                                   |
| -------------------------------------- | ------- | ------------------------------------------------------- |
| `aarch64-unknown-linux-gnu`            | 11.9 MB | `libvdo`, `libglib-2.0`, `libgobject-2.0`, glibc ≥ 2.34 |
| `thumbv7neon-unknown-linux-gnueabihf`  | 8.5 MB  | the same                                                |

Every TLS path is rustls on ring (`reqwest`'s `rustls-no-provider`, `moq-tokio`'s `ring`, iroh's `tls-ring`), so
nothing needs aws-lc-rs or OpenSSL, which keeps the cross-compile to plain GCC and a sysroot. Not yet run on a camera.

## On a camera: AXIS M5074 (ARTPEC-7, armv7hf, AXIS OS 12.5.73)

Built against SDK 12.5.0 to match the camera's OS, packaged with the SDK's `acap-build --build no-build`, and
installed and configured over VAPIX alone (`applications/upload.cgi`, `param.cgi`, `applications/control.cgi`). The
camera must allow unsigned apps (`applications/config.cgi?action=get&name=AllowUnsigned`).

- Video: VDO channel 1, H.264 High at 800×600 and 24 fps, ~100 kb/s, published to a relay on the LAN and decoded
  back out of it. VDO carries the SPS and PPS in each keyframe's header, which `StreamBuffer::data_copy` strips, so
  the agent publishes the whole buffer.
- Reports: signed by the device key, verified and schema-valid at the stand-in API, about the device and the exposure.
- iroh: homed on n0's relay; the Node iroh-http client reached `/status` by the device's public ID.
- Footprint: 18 MB resident, the camera's two cores ~5–8% busy in all while publishing.
- A relay restart: reconnected within a second, but the first QUIC attempt raced the relay starting up and the
  session fell back to WebSocket, where it stays until the next reconnect.

```sh
# Configure and start (parameters are the app's, grouped as root.Conservationtv_edge_agent).
curl --basic -u root:… -G http://<camera>/axis-cgi/param.cgi --data-urlencode action=update \
  --data-urlencode root.Conservationtv_edge_agent.DeviceSecretKey=<hex> \
  --data-urlencode root.Conservationtv_edge_agent.MoqUrl=http://<relay>:4443/anon \
  --data-urlencode root.Conservationtv_edge_agent.MoqBroadcast=<name>
curl --basic -u root:… "http://<camera>/axis-cgi/applications/control.cgi?action=start&package=conservationtv_edge_agent"
curl --basic -u root:… "http://<camera>/axis-cgi/admin/systemlog.cgi?appname=conservationtv_edge_agent"
```
